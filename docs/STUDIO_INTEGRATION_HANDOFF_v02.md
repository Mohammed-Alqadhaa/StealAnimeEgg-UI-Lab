### 2.3 Behaviour

**Default mode is VALIDATE + REPORT only.** It never moves, rotates or rescales imported pieces. It reports:
* piece count;
* missing, duplicate and unexpected pieces;
* dimensions, with delta;
* relative position, with delta after the common import offset;
* rotation angle;
* a **~100×** ("re-import at scale 0.01") or **~0.01×** ("collapsed") scale diagnosis;
* Material/Color/Transparency/CanCollide mismatches.

Appearance is reported separately from geometry PASS/FAIL, because raw FBX imports arrive gray.

**Explicit options:**
* `{ restore = true }` restores Material, Color, Transparency, CanCollide and CanTouch from the manifest, then
  re-checks.
* `{ build = true }` creates `V02_Colliders` (invisible gameplay colliders) and `V02_VFX` (anchor attachments,
  egg anchors included).

### 2.5 Usage

1. Put `StagingValidateRestore` plus the 7 data modules (named `MHA`, `DragonBall`, … `SoloLeveling`) under
   `ServerStorage.SAE_WorldStaging`.
2. Run:

```lua
local T = require(game.ServerStorage.SAE_WorldStaging.StagingValidateRestore)
T.run("DragonBall", workspace.STAGING.DragonBall_Combined_Final)                     -- validate + report
T.run("DragonBall", workspace.STAGING.DragonBall_Combined_Final, { restore = true }) -- explicit restore
T.run("DragonBall", workspace.STAGING.DragonBall_Combined_Final, { build = true })   -- explicit colliders/anchors
```
