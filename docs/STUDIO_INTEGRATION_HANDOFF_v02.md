## 2. Solo Leveling export recovery (done here)

### 2.1 The three filename collisions

These were determined from the committed `art/exports/worlds/08_SoloLeveling/manifest.json` (48 entries, only
45 FBX files on disk). In each case the surviving file on disk was re-imported and checked.

| Filename | Fabric group (cape, `#0d0f16`) | Neon group (eyes, `#39b5ff`) | Survived on disk |
|---|---|---|---|
| `ShadowArmy.fbx` | 13,028 tris | 480 tris | Neon (the eyes); **the capes were lost** |
| `Colossi.fbx` | 1,308 tris | 48 tris | Neon; **the capes were lost** |
| `EndGuards.fbx` | 2,612 tris | 96 tris | Neon; **the capes were lost** |

**Root cause** (in `tools/blender/sae_bpy.py`):
* A collection with a single material exported under the bare module name.
* The knight builder puts capes and eyes into separate collections that share a module name
  (`EXPORT_ShadowArmy__Fabric` and `EXPORT_ShadowArmy__Neon`), so both wrote `ShadowArmy.fbx`.

### 2.2 Fix

* **New naming rule, `module_groups()`:** a piece keeps the bare module name only if the module belongs to one
  collection and has one material. Otherwise it gets a material suffix, and names are asserted unique.
* **Effect on other worlds:** checked against every committed manifest. Only Solo Leveling changes; the other six
  keep identical names.
* **New Solo Leveling pieces:** `ShadowArmy_ShadowCape`, `ShadowArmy_ShadowEyes`, `Colossi_ShadowCape`,
  `Colossi_ShadowEyes`, `EndGuards_ShadowCape`, `EndGuards_ShadowEyes`.

## 3. Studio staging tools (new; for use in Studio on Windows)

* **`tools/studio/world_data/<World>.lua`** (7 files), generated by `tools/studio/gen_world_data.py` from the
  manifests (Solo Leveling uses the recovered one). Each contains:
  * the expected pieces: name, size, position, Material, Color, Transparency, CanCollide and layer;
  * the anchors;
  * the gameplay colliders;
  * the egg-anchor count.
* **`tools/studio/StagingValidateRestore.lua`**, a Studio command-bar ModuleScript. It:
  * validates a combined-scene import: 100% of pieces present, no duplicates or unexpected pieces, size, relative
    position, rotation, and **100× / collapsed-scale detection**;
  * optionally restores the manifest's Material, Color, Transparency and CanCollide (FBX arrives gray);
  * optionally builds the `V02_Colliders` and `V02_VFX` anchors (egg anchors included).
* **Offline test:** `tools/studio/tests/staging_validator_test.luau` (Lune). Result: **35/35 PASS**. For each of
  the 7 worlds it confirms that a correct import passes, the egg-anchor count is right (JJK = 6), and a missing
  piece, a 100× scale error and a moved piece are each detected. This is an offline test with synthetic parts, **not
  a Studio test**.

**Usage in Studio:**
1. Put `StagingValidateRestore` and the 7 data modules (as ModuleScripts named after the world) under
   `ServerStorage.SAE_WorldStaging`.
2. Run:
   `require(game.ServerStorage.SAE_WorldStaging.StagingValidateRestore).run("SoloLeveling", <imported model>, { restore = true, build = true })`.
